# Response to "ubuntils 2.3.0 — a practitioner's review"

*Published 2026-11-10. The review itself is in this directory
(`2.3.0-practitioner-review.pdf`). Status is tracked against the development
branch for 3.0; each row names the plan ID that delivers it
(`docs/plans/id-registry.md`).*

Thank you to the reviewer, who read the collectors, the rules, the bundle and
timeline code, the pipeline and the security notes closely enough to walk nine
intrusions through them by hand, and who was precise about what they did and
did not check. A review that names commit-level evidence and ranks its own
recommendations is the most useful kind a solo project can get, and this one
is being acted on almost entirely.

The review changed the 3.0 plan in three ways. **First, order.** The 3.0 plan
had a single-file build, a coverage benchmark and better grouping, but treated
breadth as something to add after the refactors. We now ship a 2.4.0 release
first with the fixes for the reviewer's three biggest worries (C1–C3) plus
most quick wins, and we run the PANIX benchmark *before* adding new rules, so
its misses decide what comes next. **Second, positioning.** We are adopting the
reviewer's pitch ("a persistence-focused second opinion with explainable
scoring") and moving remediation out of the headline. **Third, proof.** Each
release will publish its benchmark and clean-host results, misses included.

Two things in the review were already partly addressed on the 3.0 branch when
it arrived: output now carries a schema version and ATT&CK technique IDs. Where
we read the code differently from the reviewer, the table says so and why.

**Verdict key:** *agree* = confirmed in the code, work planned; *partly* = the
core point stands but a detail differs; *disagree* = we think the code shows
otherwise. **Target:** 2.4.0 is a non-breaking release cut from the 3.0
branch; 3.0.0 milestones are alpha.1 → alpha.2 → beta.1 → beta.2 → GA.

## The nine missed intrusions

| # | Intrusion | Verdict | What we did or will do | Plan ID | Target |
|---|---|---|---|---|---|
| C1 | Key added to an `authorized_keys` that is older than 7 days | agree | Every key is inventoried with its fingerprint at LOW, whatever the file's age; baselines quiet the known ones. Inventory doesn't count against the noise budget. | E8-S4, E3-S7 | 2.4.0 |
| C2 | `/dev/shm` implant with an ordinary name, idle or listening | agree | Processes are flagged by location (temp dir, deleted, memfd), whatever their name, and listeners are reported. Tested not to fire on Python virtualenvs under `/opt` or `/home`. | E8-S7 | 2.4.0 |
| C3 | Root `/etc/cron.d` entry running a `/dev/tcp` reverse shell | agree | A new `CRON_SUSPICIOUS_COMMAND` rule runs every cron entry through the shared matcher, whoever owns it. | E8-S1, E8-S2 | 2.4.0 |
| C4 | Tidy root-owned unit with `ExecStart=/usr/local/sbin/updater` | agree | "Unit file owned by no package" plus recency, using a package database read from files (so it also works offline). | E8-S3 | 3.0.0-beta.1 |
| C5 | `www-data ALL=(ALL) NOPASSWD: ALL` in `sudoers.d` | agree | `SUDOERS_NOPASSWD` evaluates every account, system accounts included. | E8-S6 | 2.4.0 |
| C6 | Service account given a login shell, or a user added to `sudo`/`docker`/`lxd` | agree | A new account-privilege rule: service accounts with login shells, recent accounts, privileged-group membership. | E8-S5 | 3.0.0-beta.1 |
| C7 | Setuid bash in `/var/lib` or `/root`; file capabilities unchecked | agree | Wider setuid search paths (2.4.0) and file capabilities read from the `security.capability` attribute, with no extra tool needed (beta.1). | E8-S8 | 2.4.0 / 3.0.0-beta.1 |
| C8 | `bash <(curl …)` in `.bashrc`, older than 48 h | partly | The miss is real and is the regex: it only knew `curl … \| sh`. File age is not the cause, because suspicious content has been reported at any age since 2.2.0. The shared matcher covers process substitution. | E8-S1, E8-S14 | 2.4.0 |
| C9 | `LD_PRELOAD` via a systemd `Environment=` line; `LD_AUDIT` unchecked | agree | Unit `Environment=`/`EnvironmentFile=`, `LD_AUDIT`, `LD_LIBRARY_PATH` and `ld.so.conf.d` are all read. | E8-S9 | 3.0.0-beta.1 |

## What we are keeping

The review listed strengths it wanted preserved. Each is now a release criterion
or a test: the "Not covered" list; "could not look" never reading as clean;
the hostile-host posture (isolated re-exec, install trust check, bounded
reads, symlink-free writes, attacker-text parsing); dry-run-default
remediation with hard blocks; explainable signals; depth in sudoers, SSH,
drop-ins and kernel taint; CI hygiene; and no network calls.

## A note on method

The reviewer read the code and did not run it. We checked every claim against
the code before writing this response (file and line references are in
`docs/plans/id-registry.md`), and we will publish measured results for the
items above as each release ships. Where those results disagree with this
table, the results win, and this file will be updated.
